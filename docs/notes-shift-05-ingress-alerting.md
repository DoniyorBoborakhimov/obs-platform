Ingress + Alertmanager
Ставим ingress-nginx, убираем port-forward, получаем RED-метрики входящего трафика.
Затем настраиваем Alertmanager: правила, маршрутизация, борьба с шумом.
### Дрейф часов ломает метрики

Симптом: process_start_time_seconds растёт на 1 сек каждый скрейп,
хотя по определению это КОНСТАНТА (момент старта процесса).

Причина: метрика вычисляется как "текущее время минус uptime".
Часы в WSL2 дрейфуют (особенно после сна хоста) -> значение плывёт
-> changes() считает каждое колебание -> алерт горит вечно.

ПОЧЕМУ ЭТО ВАЖНО ШИРЕ:
рассинхронизация времени ломает не только этот алерт:
- корреляция логов и метрик между хостами разъезжается
- TLS-сертификаты "истекли" или "ещё не действительны"
- Kerberos/LDAP-аутентификация отваливается (жёсткое окно ~5 мин)
- распределённые системы с кворумом принимают неверные решения
- в банке: расхождение времени в транзакционных логах = проблема аудита

Поэтому NTP/chrony — базовая инфраструктура, а не мелочь.
Мониторить обязательно: node_timex_offset_seconds, node_timex_sync_status

Починка в WSL:
  wsl --shutdown         (из PowerShell, пересоздаёт виртуалку с новым временем)
  sudo hwclock -s        (внутри WSL, синхронизировать с аппаратными часами)
